How it works

      
The model writes intent. A compiler writes blocks.

      

        The obvious approach is to let the model place blocks. That is what this
        project used to do, and a castle cost tens of thousands of tokens and just
        as many server commands. So the blocks stopped being the model's problem.
      

    


    

      

        

          
It looks at where you are standing

          

            One call returns the site: your position and facing, the biome, ground
            height and slope, and what is nearby — as statistics, not as a list of
            every surface block. Eight numbers instead of four thousand objects.
          

        

      

      

        

          
It writes a blueprint

          

            About sixty lines of JSON describing intent: a cylinder here, a hip roof
            there, four corner towers by symmetry. {"op":"cylinder","r":4,"h":22}
            is eighty characters and eleven hundred blocks.
          

        

      

      

        

          
The compiler turns it into commands

          

            Shapes become voxels, voxels merge into maximal runs of identical
            material, and each run becomes one /fill. A wall of 1,184
            blocks ships as four commands. Deterministic, offline, ~130 ms.

The format

      
Twenty-three ops. Small enough to write by hand.

      

        Drop a JSON file in blueprints/
        and it becomes buildable by name. Drop one in
        styles/ and every structure
        can wear it.
      

    


    

      boxshellwallsframe
      cylindersphereconepyramid
      roofarchbattlementsspiral
      linesetwindowsdoor
      scatterclearfoundation
      grouprepeatsymmetryprefab
    


    

// four corner towers, written once
{ "op": "symmetry", "axis": "xz", "about": 20, "of": [
  { "op": "cylinder", "at": [-2,0,-2], "r": 4, "h": 18,
    "block": "@stone", "hollow": true },
  { "op": "battlements", "at": [-3,19,-3], "size": [11,2,11] }
]}


    

      
Roofs get their stairs facing the right way

      

        In vanilla, a stair's facing
        names the side holding its full-height half — so on a slope, stairs face
        uphill. Face them the other way and every step leaves a half-block
        gap. It is the single detail that separates a roof that looks built from a
        roof that looks generated, and the compiler handles it.
      

    

  







  

    

      
Get it

      
Two minutes, or zero if you just want to look.

    


    

      

        
Try it with no server

        

# clone, install, run
git clone https://github.com/LePro10/mcAi
cd mcAi && npm install
./mcai serve --sim

# or in a container, with a server
docker compose up -d

        

          Node 20+ and nothing else. No account, no login, no API key needed to
          start — the fifteen built-in structures build without any AI at all.
        

      


      

        
Run it on your server

        

# server.properties
enable-rcon=true
rcon.password=pick-something

# then
export RCON_PASSWORD=pick-something
./mcai setup   # pick any AI provider
./mcai serve

        

          Paper, Spigot, Fabric or vanilla, 1.20+. Fourteen AI providers to choose
          from — Anthropic, OpenAI, Gemini, OpenRouter, DeepSeek, Groq, Mistral,
          xAI, and local Ollama or LM Studio, which cost nothing at all.
        

      

    


    

      
Or build from the editor you already use

      

        mcAI is an MCP server. Point Claude Code, Claude Desktop or Cursor at it and
        build in your world from there — including
        mc_preview, which
        compiles and renders a design with no server running at all.
      

      
{ "mcpServers": { "mcai": { "command": "node", "args": ["/path/to/mcAi/dist/mcp/main.js"] } } }
